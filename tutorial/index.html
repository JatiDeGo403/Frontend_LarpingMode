Bagian 1 — HTML

Inti dari seluruh handbook. HTML menentukan struktur dan makna dari setiap konten di halaman — fondasi yang tidak bisa digantikan oleh CSS, JavaScript, atau framework apapun.

01

Cara Kerja Web di Balik Layar

Sebelum belajar tag-tag HTML, pahami dulu apa yang terjadi ketika kamu mengetik alamat di browser. Tanpa paham ini, banyak konsep lain akan terasa abstrak.

1.1 Anatomi URL

Setiap alamat web punya struktur yang konsisten:

url
https://www.example.com:443/path/page.html?key=value#section

│      │             │   │        │             │
│      │             │   │        │             └─ Fragment (bagian tertentu di halaman)
│      │             │   │        └─────────────── Query string (data ke server)
│      │             │   └──────────────────────── Path (halaman/resource)
│      │             └──────────────────────────── Port (default 443 untuk https)
│      └────────────────────────────────────────── Host / domain
└───────────────────────────────────────────────── Protokol (https = aman)

Ingat begini saja dulu

Semua yang sesudah ? disebut query string — tempat kita mengirim data ke server (misal form search). Semua yang sesudah # disebut fragment — navigasi ke elemen tertentu di halaman yang sama.

1.2 Apa yang terjadi saat kamu buka example.com

Ada 7 langkah besar yang terjadi setiap kali kamu menekan Enter:

  1. DNS lookup — komputer menanyakan "di mana alamat IP example.com?" ke DNS server. Jawaban: misalnya 93.184.216.34.
  2. TCP handshake — browser membuka koneksi ke server IP tersebut dan menyepakati jalur komunikasi.
  3. TLS handshake — koneksi dienkripsi dengan sertifikat SSL (untuk https). Ini yang bikin ikon gembok di address bar.
  4. HTTP request — browser mengirim permintaan: GET / HTTP/1.1 plus header (User-Agent, Accept, dll).
  5. HTTP response — server membalas dengan status code (200 OK, 404, 500) plus isi <html>...</html>.
  6. Parse & render — browser membaca HTML, lalu meminta CSS, JS, gambar, dan font untuk "merakit" tampilan visual.
  7. Interaksi — halaman hidup: klik, scroll, isi form. Semua diproses oleh JavaScript.

1.3 Peran Tiga Bahasa Inti

Frontend modern berdiri di atas tiga bahasa yang masing-masing punya satu tugas:

BahasaPeranAnalogi
HTMLStruktur & makna kontenTulang & organ tubuh
CSSPenampilan & layoutPakaian & aksesoris
JavaScriptPerilaku & interaksiGerik & refleks

Prinsip Golden

Selalu mulai dari HTML yang valid dan semantik. CSS dan JS adalahpelengkap — kalau HTML-nya sudah benar, halaman tetap terbaca meskipun CSS gagal dimuat. Sebaliknya, tanpa HTML yang baik, CSS sehebat apa pun tidak akan menyelamatkan.

1.4 Client vs Server

Client = perangkat kamu (browser). Server = komputer yang menyimpan dan mengirim data. Perbandingan singkat:

Client (Browser)Server
ContohChrome, Firefox, SafariKomputer hosting / VPS
BertugasRender, kirim requestSimpan data, proses, kirim response
BahasaHTML, CSS, JSPHP, Python, Node.js, Go, dsb.
Contoh kodeValidasi form di sisi userSimpan ke database

Yang kamu pelajari di handbook ini adalah sisi client — frontend. Tapi ingat: validasi sungguhan (misalnya memastikan password benar) harus tetap dilakukan di server. Validasi di browser hanya untuk kenyamanan pengguna (user experience), bukan keamanan.

⚠️ mitos yang harus dibuang

"Kalau saya sembunyikan elemen pakai display:none, berarti aman." — Tidak. siapa pun yang membuka DevTools tetap bisa melihat dan mengubah nilainya. Semua pengecekan penting harus diulang di server.

Latihan 1

Jelaskan dengan bahasa sendiri: apa bedanya halaman yang statis dengan halaman yang dinamis? Kapan masing-masing lebih tepat dipakai?

Buka kunci jawaban

Gunakan kerangka: definisi → cara kerja → contoh kasus.

  • Statis: isi kontennya sudah ada di file HTML, tidak berubah tiap request. Contoh: landing page, dokumen, artikel blog. Lebih cepat, mudah di-cache, murah di-hosting.
  • Dinamis: isi dirakit saat runtime oleh server (mengambil dari database/API). Contoh: dashboard admin, halaman login, inbox email. Personalisasi & data real-time, tapi butuh server + query.

Pilihan lain: SPA (single page app) dihitung dinamis karena JS menyusun DOM di client, meski sering tanpa server-side logic langsung.

02

Sintaks Dasar HTML

HTML adalah bahasa markup — bukan bahasa pemrograman. Tidak ada variabel, logika, atau loop. Tugasnya satu: memberi struktur dan makna pada konten.

2.1 Dokumen HTML paling minimal

Setiap file HTML modern punya lima "wajib utama" ini:

html
<!DOCTYPE html>
<html lang="id">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Judul Halaman</title>
</head>
<body>
  <h1>Halo, dunia!</h1>
  <p>Ini paragraf pertama saya.</p>
</body>
</html>
BarisFungsiKenapa wajib
<!DOCTYPE html>Dokument modeMemberi tahu browser: "ini HTML5, pakai mode standar (bukan quirks mode)". Tanpa ini, rendering bisa meleset.
lang="id"Bahasa halamanMembantu screen reader memilih pronunciation yang tepat, dan memengaruhi rendering teks (mis. tanda baca).
charset="UTF-8"Encoding karakterTanpa ini, huruf seperti "é" atau emoji bisa jadi kotak-kotak aneh.
viewportKonfigurasi tampilan mobileAgar responsif bekerja; tanpa ini halaman akan ter-zoom out di HP.
<title>Judul di tab browserWajib untuk aksesibilitas & SEO; screen reader membacanya untuk mengumumkan halaman.

Doctype hanya boleh satu

Hanya ada satu <!DOCTYPE html> di paling atas file, sebelum tag <html>. Jangan pakai DOCTYPE lama seperti HTML 4.01 atau XHTML — sudah deprecated.

2.2 Element, Tag, dan Atribut

Istilah yang sering tertukar:

  • Element = keseluruhan unit dari tag pembuka sampai tag penutup, termasuk isinya. Contoh: <p>Halo</p>.
  • Tag = penanda di dalam kurung sudut. Ada tag pembuka (<p>) dan tag penutup (</p>).
  • Atribut = informasi tambahan pada tag pembuka. Format: nama="nilai".
html
<a href="https://mdn.mozilla.org" class="link utama" target="_blank">MDN</a>
   │      │                        │                │        │
   │      │                        │                │        └─ nilai atribut
   │      │                        │                └────────── nama atribut
   │      │                        └─────────────────────────── atribut kedua
   │      └─────────────────────────────────────────────────── atribut pertama
   └────────────────────────────────────────────────────────── nama element (tag)

Urutan_atribut bebas

Browser tidak peduli urutan atribut. class="x" id="y" dan id="y" class="x" hasilnya sama. Yang penting: setiap atribut dipisah spasi, dan nilai yang mengandung spasi diapit tanda kutip.

2.3 Void Element (Elemen Tanpa Tag Penutup)

Beberapa elemen tidak butuh konten di dalamnya, jadi tidak punya tag penutup. Ini namanya void element:

html
<br>      <hr>       <img src="foto.jpg">
<input>   <meta charset="UTF-8">   <link rel="stylesheet" href="style.css">

Perhatikan: jangan menulis <br></br> atau <img ...></img> — itu tidak valid HTML. Tag penutup they've diabaikan browser, tapi validator akan protes.

2.4 Pen nests & Aturan Validitas

Elemen harus di-nest dengan benar: tag yang dibuka harus ditutup sebelum membuka tag di luarnya ("last in, first out").

html
<!-- BENAR: <p> dibuka lalu ditutup, baru <div> -->
<div>
  <p>Paragraf di dalam div</p>
</div>

<!-- SALAH: <p> masih terbuka saat <div> ditutup -->
<div>
  <p>Paragraf yang belum ditutup
</div>              ← browser akan auto "tutup" <p> di sini, bikin struktur berantakan

Semua elemen yang boleh jadi anak elemen lain punya aturan spesifik (mis. <p> tidak boleh berisi <div> atau heading). Aturan ini akan dibahas di Bab 11 — Content Categories.

2.5 Komentar

Komentar tidak ditampilkan di browser, berguna untuk catatan atau memblokir bagian kode sementara:

html
<!-- Ini komentar satu baris -->

<!--
  Komentar multi-baris.
  Berguna untuk menonaktifkan blok HTML sementara:
  <div class="sedang-dikerjakan">...</div>
-->

2.6 Case Sensitivity

HTML tidak case-sensitive untuk nama tag dan atribut — <P> sama dengan <p>. Tapi nilai atribut dan isi teks tetap case-sensitive. Biasakan tulis lowercase untuk konsistensi.

03

Struktur Dokumen & Meta di <head>

Elemen <head> berisi metadata — informasi tentang dokumen yang tidak ditampilkan di halaman, tapi dibaca oleh browser, mesin pencari, dan media sosial.

3.1 Meta Tag Penting

Charset & Viewport

html
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1">

Selalu letakkan charset di 1024 karakter pertama (biasanya baris pertama setelah DOCTYPE) agar browser membacanya sebelum konten. Viewport wajib untuk website responsive.

Title & Description

html
<title>Belajar HTML dari Nol — Panduan Lengkap</title>
<meta name="description" content="Panduan belajar HTML lengkap dari dasar hingga advanced. Cocok untuk pemula maupun developer.">
  • <title> — muncul di tab browser, hasil cari (SERP), dan saat bookmark. Tulis unik per halaman.
  • description — ringkasan yang muncul di bawah judul di hasil pencarian. Panjang ideal 150–160 karakter.

Open Graph & Twitter Card

Saat link kamu dibagikan ke WhatsApp, Facebook, atau X, halaman ini yang menentukan tampilan preview-nya:

html
<meta property="og:type" content="website">
<meta property="og:title" content="Judul untuk preview">
<meta property="og:description" content="Deskripsi singkat untuk preview">
<meta property="og:image" content="https://contoh.com/preview.jpg">
<meta property="og:url" content="https://contoh.com/halaman">
<meta name="twitter:card" content="summary_large_image">

Theme Color & Base

html
<meta name="theme-color" content="#3b6ef6">
<base href="https://contoh.com/">

theme-color mengubah warna address bar di browser mobile. <base> menetapkan URL dasar untuk semua link relatif — berguna, tapi jarang dipakai karena bisa membingungkan path absolut.

Link ke CSS, Font, dan Favicon

html
<link rel="stylesheet" href="assets/css/main.css">
<link rel="icon" href="/favicon.ico" sizes="any">
<link rel="icon" type="image/svg+xml" href="/icon.svg">
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preload" href="hero.jpg" as="image">

preconnect vs preload

preconnect = buka koneksi ke server sebelum perlu (hemat handshake). preload = unduh resource segera sebelum diminta. Untuk gambar hero yang tampil di atas layar, preload sering donner Folgen besar pada LCP.

3.2 Resource Hints (Performance)

HintFungsiPakai Untuk
rel="preconnect"Buka koneksi TCP/TLS duluanFont Google, CDN analytics
rel="dns-prefetch"Resolve DNS sajaDomain yang jarang, non-kritis
rel="preload"Unduh resource penting sekarangFont, gambar LCP, CSS utama
rel="modulepreload"Preload ES moduleBundle JS modular
rel="prefetch"Unduh untuk navigasi berikutnyaPagination, halaman detail

Jangan over-preload

Preload yang berlebihan justru memperlambat halaman (membandyakan bandwidth & CPU parse). Maksimal 3–5 hint per halaman, dan hanya untuk resource yang benar-benar kritis.

3.3 Atribut http-equiv (Langka, tapi perlu tahu)

html
<!-- Ganti halaman otomatis setelah 5 detik (jarang dipakai, annoyed users) -->
<meta http-equiv="refresh" content="5;url=https://contoh.com">

<!-- Paksa mode standards (legacy; sekarang cukup pakai DOCTYPE) -->
<meta http-equiv="X-UA-Compatible" content="IE=edge">

04

Heading, Paragraf & Teks

Heading adalah elemen paling penting untuk SEO dan aksesibilitas —(screen reader) memakainya untuk membuat "peta" halaman.

4.1 Heading h1–h6

html
<h1>Judul Utama Halaman</h1>
<h2>Bagian Besar</h2>
<h3>Sub-bagian</h3>
<h4>Detail</h4>
<h5>Sub-detail</h5>
<h6>Keterangan terkecil</h6>

Aturan heading yang sering dilanggar

  • Satu <h1> per halaman — itu identitas halaman.
  • Jangan skip level. Boleh h1 → h2 → h3, tapi jangan h1 → h3. Skip level membingungkan screen reader.
  • Jangan pakai heading untuk style. Butuh teks besar? Pakai CSS, bukan <h1>.
  • Heading bukan untuk SEO tricks. Google understands semantics; menyalahgunakan heading = Ranking bisa turun.

4.2 Paragraf & Line Break

html
<p>Ini paragraf normal. Spasi dan baris baru di dalam paragraf otomatis dirapikan oleh browser.</p>

<p>Baris pertama<br>Baris kedua setelah line break.</p>

<p>Gabungan<br><br>dengan double break = paragraf baru secara visual.</p>

Ingat ctrl sospial

HTML mengabaikan spasi berlebih dan baris baru di dalam teks. Kalau butuh jarak, pakai CSS (margin), bukan banyak &nbsp; atau <br>.

4.3 Penekanan & Makna

Banyak orang mengira <b> = bold dan <i> = italic. Padahal, keduanya punya makna semantik:

ElementArti SemantikKapan Pakai
<strong>Penting / urgensiPeringatan, poin kunci. Default: bold
<em>Penekanan stressSapaan, istilah asing, judul buku. Default: italic
<b>Bold tanpa makna khususKeyword di heading, nama produk. Default: bold
<i>Italic tanpa makna khususIkon, Foreign words. Default: italic
<mark>Teks yang disorotHasil pencarian, jawaban benar

Tes cepat: bukan tampilan, tapi makna

Tanya: "Kalau saya baca teks ini di browser tanpa CSS, apakah saya masih paham maksudnya?" Kalau iya → semantik benar. Kalau tidak → kamu salah pakai elemen.

List, Kutipan & Kode

Ada tiga jenis list di HTML. Memilih yang tepat penting untuk semantics.

5.1 Tiga Jenis List

Unordered list (<ul>) — poin/bullet

html
<ul>
  <li>Beras</li>
  <li>Minyak goreng</li>
  <li>Gula</li>
</ul>

Ordered list (<ol>) — bernomor

html
<ol>
  <li>Cuci GRATIS paket</li>
  <li>Isi ulang air</li>
  <li>Cuci mobil</li>
</ol>

<!-- Mulai dari angka tertentu -->
<ol start="5">
  <li>Langkah kelima</li>
  <li>Langkah keenam</li>
</ol>

<!-- Ganti penanda -->
<ol type="A">
  <li>Pilihan A</li>
  <li>Pilihan B</li>
</ol>

Description list (<dl>) — istilah & definisi

html
<dl>
  <dt>HTTP</dt>
  <dd>HyperText Transfer Protocol — protokol untuk transfer data web.</dd>
  <dt>HTML</dt>
  <dd>HyperText Markup Language — bahasa markup untuk struktur halaman.</dd>
</dl>

DL juga untuk detail produk

Banyak situs e-commerce memakai <dl> untuk spesifikasi: <dt> = label ("Warna"), <dd> = nilai ("Merah"). Satu <dt> boleh punya beberapa <dd>.

5.2 Atribut List

html
<li value="7">Item dengan nomor custom</li>

<ul style="list-style-type: square">
  <li>Bullet kotak</li>
</ul>

<!-- List tanpa penanda, tapi tetap semantik list -->
<ul style="list-style: none; padding-left: 0">
  <li>Navigasi horizontal</li>
  <li>Menu sosial</li>
</ul>

Jangan hilangkan semantik list

Mengganti <div> dengan CSS untuk menu navigasi berarti kehilangan makna "daftar link" bagi screen reader. Tetap pakai <ul>/<li>, buang penandanya lewat CSS saja.

5.3 Kutipan

<q>Kutipan singkat di dalam paragraf. Otomatis menambah tanda kutip (“…”).
<blockquote>Kutipan panjang dari sumber lain. Tampilkan sebagai blok terpisah.
<cite>Merujuk pada judul karya (buku, artikel, film). Bukan untuk nama orang.

6.2 Jenis URL

html
<!-- 1. Absolut: lengkap dengan protokol -->
<a href="https://google.com">Google</a>

<!-- 2. Relatif: relatif terhadap folder file sekarang -->
<a href="about.html">Tentang</a>                <!-- file di folder sama -->
<a href="pages/produk.html">Produk</a>        <!-- subfolder -->
<a href="/dashboard">Dashboard</a>          <!-- dari root domain -->
<a href="../index.html">Beranda</a>           <!-- naik satu folder -->

<!-- 3. Fragment: navigasi di halaman yang sama -->
<a href="#kontak">Langsung ke section Kontak</a>

<!-- 4. Protokol khusus -->
<a href="mailto:halo@contoh.com">Kirim email</a>
<a href="tel:+6281234567890">Telepon kami</a>
<a href="https://wa.me/6281234567890">Chat WhatsApp</a>
<a href="sms:+6281234567890">Kirim SMS</a>

Perhatikan path relatif

Kalau halaman kamu di /blog/artikel.html dan menulis href="about.html", browser akan mencari /blog/about.html. Untuk link yang paling aman lintas halaman, pakai path absolut dari root: href="/tentang".

6.3 Men_sha Non-HTTP (Penting untuk Keamanan)

html
<!-- target="_blank" tanpa rel="noopener" = risiko "reverse tabnabbing" -->
<a href="https:// situs-luar.com" target="_blank">Buka situs luar</a>   <!-- BERBAHAYA -->

<!-- WAJIB tambahkan noopener -->
<a href="https://situs-luar.com" target="_blank" rel="noopener noreferrer">Buka situs luar</a>

⚠️ Ancaman reverse tabnabbing

Tanpa noopener, halaman yang dibuka di tab baru bisa memperoleh akses ke objek window.opener milik halaman kamu, lalu menavigasi halaman asli ke situs palsu. Browser modern sudah otomatis mengaktifkan noopener untuk target="_blank", tapi tetap tulis eksplisit — biayanya nol dan aman untuk browser lama.

6.4 Tautan Aksesibel & Best Practice

  • Link harus jelas — avoid "klik di sini". Tulis "Baca panduan lengkap" agar jelas tujuannya.
  • Buka di tab baru hanya jika perlu — navigasi membingungkan pengguna. Defaultnya cukup link biasa.
  • Warnsai link eksternal — beri ikon atau keterangan, jangan sampai user terkena halaman palsu.
  • Pakai aria-label jika teks link kurang deskriptif dan isi visual tidak terbaca.
html
<!-- Buruk: tidak jelas -->
<a href="/harga">klik di sini</a>

<!-- Bagus: deskriptif -->
<a href="/harga">Lihat daftar harga lengkap</a>

<!-- Link dengan konteks tambahan untuk screen reader -->
<a href="/panduan" aria-label="Baca panduan HTML (dokumen PDF)">
  Panduan HTML <span aria-hidden="true">↗</span>
</a>

html

7.2 Gambar Responsif: srcset & sizes

html

Format Modern: <picture>

html

Format apa yang perlu didukung?

Urutan dukungan saat ini: AVIF (paling hemat, ~50% dari JPEG) → WebP (~30% lebih kecil) → JPEG/PNG (fallback universal). Browser hanya mengambil <source> pertama yang didukung — jadi selalu taruh format yang paling baik di atas.

Tabel HTML & Aksesibilitas

Tabel bukan hanya untuk data angka. Tapi kalau datanya memang berbentuk baris-kolom, tabel HTML jauh lebih baik daripada sekadar kumpulan <div> — karena screen reader bisa mengbacanya sebagai tabel sungguhan.

TABEL bukan untuk layout

Di era tables-based layout (1995–2000), <table> dipakai untuk mengatur posisi elemen. Sekarang itu anti-pattern: bikin halaman lambat, sulit diakses, dan mustahil dibuat responsif. Pakai Flexbox/Grid (Bab 17) untuk layout, <table> hanya untuk data tabular.

8.2 scope — Kunci Aksesibilitas Tabel

Tanpa scope, screen reader tidak tahu kolom mana yang sedang dibaca:

html

<th scope="col">Negara</th>

<th scope="row">  <!-- ini header untuk satu BARIS -->
<th scope="row">Indonesia</th>

<th scope="colgroup">  <!-- header untuk sekelompok kolom -->
<th scope="rowgroup">  <!-- header untuk sekelompok baris -->

Contoh: user menekan tombol "M" di VoiceOver untuk hear "merpati" pada tabel — dengan scope, user mendengar "merpati,Github, Asia". Tanpa itu, hanya "merpati, Asia".

11.5 tabindex yang Benar

html
<!-- Tabi urut alami: tidak perlu tabindex sama sekali -->

<button>Tombol B</button>

<!-- 0 = bisa difokus, urutan mengikuti DOM (biasanya jangan dipakai) -->
<div tabindex="0">Area ini bisa difokus</div>

<!-- -1 = hanya bisa difokus lewat JS, tidak muncul di urutan Tab -->
<button tabindex="-1">Tombol dialog (fokus otomatis saat dibuka)</button>

<-- ❌ JANGAN memakai tabindex positif besar -->
<button tabindex="999">Ini merusak urutan fokus natural</button>

Positive tabindex = jebakan fatal

Memberi tabindex positif membuat browser menyusun ulang urutan Tab berdasarkan angka itu — dan elemen dengan tabindex="0" (default) selalu dilompati. Hasilnya pengguna tidak bisa menjangkau bagian halaman kamu lewat keyboard. Aturan: gunakan 0 atau -1, atau lebih baik jangan sama sekali.

Semantic HTML & Aksesibilitas

Aksesibilitas (a11y) bukan fitur tambahan — ini bagian dari menulis HTML yang benar. Prinsipnya sederhana: pakai elemen yang tepat, dan bisa tetap berfungsi.

12.1 Empat Prinsip Dasar (WCAG)

  1. Perceivable — konten harus bisa dilihat atau didengar (alt text, subtitle, kontras warna).
  2. Operable — semua fungsi bisa diakses via keyboard, tanpa perlu mouse.
  3. Understandable — struktur dan bahasa harus jelas (heading berurutan, label deskriptif).
  4. Robust — kompatibel dengan screen reader dan teknologi bantu terkini.

12.2 ARIA singkatan dari Accessible Rich Internet Applications

ARIA menambah atribut pada HTML untuk komunikasi tambahan ke screen reader:

html
<!-- Role: menetapkan peran elemen -->
<div role="button" tabindex="0">Klik saya</div>

<!-- Accessible name: memberi nama yang dibaca screen reader -->
<button aria-label="Tutup dialog">×</button>

<img src="ikon.svg" alt="" role="presentation">

<!-- State: menjelaskan kondisi saat ini -->
<button aria-expanded="false" aria-controls="menu">Menu</button>
<button aria-pressed="true">Bold</button>
<div aria-live="polite">Pesan ini akan dibacakan otomatis</div>

<!-- Relasi antar elemen -->
<input type="text" id="pwd"
       aria-describedby="pwd-help"
       aria-describedby="pwd-error">
<span id="pwd-help">Minimal 8 karakter</span>

12.3 Aturan Emas ARIA

The first rule of ARIA

Jangan pakai ARIA jika sudah ada elemen HTML native yang melakukan hal sama.

html
<!-- ❌ ARIA berlebihan -->
<div role="button" tabindex="0" aria-pressed="false"
     onclick="toggle()">Bold</div>

<!-- ✅ Elemen native jauh lebih baik -->
<button type="button" aria-pressed="false" onclick="toggle()">Bold</button>

Elemen native sudah punya semantics, dukungan keyboard, manajemen fokus, dan style yang bisa diubah — semuanya gratis. ARIA hanya menambah, tidak pernah menggantikan.

Prinsip ini berlaku untuk developer

Elemen yang butuh ARIA agar berfungsi penuh berarti arsitekturnya sudah salah sejak awal. Kalau kamu butuh role + tabindex + onkeydown untuk membuat <div> jadi tombol, seharusnya kamu pakai <button> sejak awal.

12.6 Fokus yang Terlihat

Jangan pernah menghapus outline tanpa pengganti

outline: none tanpa gaya :focus-visible membuat pengguna keyboard buta — mereka tidak tahu sedang berada di mana. Kalau memang perlu menyembunyikan outline, ganti dengan indikator fokus yang jelas.

css
/* ❌ Buruk */

/* ✅ Bagus: fokus jelas, hanya saat perlu */
button:focus-visible {
  outline: 3px solid var(--accent);
  outline-offset: 2px;
}

/* Untuk elemen yang fokus via JS */
[tabindex="-1"]:focus { outline: none; }

    position: absolute;
    width: 1px; height: 1px;
    padding: 0; margin: -1px;
    overflow: hidden;
    clip: rect(0, 0, 0, 0);
    white-space: nowrap;

sr-only ("screen reader only") adalah pola penting: elemen terlihat normal di layar, tapi isinya hanya dibacakan screen reader. Contoh klasik: tombol hapus yang hanya menampilkan ikon × — ikonnya disembunyikan, teks "Hapus" dibaca screen reader.

12.8 Checklist Aksesibilitas

  • Semua gambar punya alt yang tepat (atau alt="" bila dekoratif)
  • Heading berurutan (h1 → h2 → h3), tanpa skip
  • Setiap input punya <label> yang terhubung
  • Semua fungsi bisa diakses keyboard
  • Indikator fokus selalu terlihat
  • Kontras teks minimal 4.5:1 (teks normal), 3:1 (teks besar)
  • Video punya subtitle (<track>)
  • Tidak ada outline: none tanpa pengganti
  • Warna bukan satu-satunya pembawa informasi
  • Ada skip link menuju <main>

Alat untuk menguji

Chrome DevTools → tab Elements → Accessibility panel (cek a11y tree). Lighthouse (DevTools → Lighthouse) untuk audit otomatis. Screen reader: aktifkan NVDA (Windows, gratis) atau VoiceOver (macOS/iOS, sudah terpasang) untuk menguji secara langsung.

Web Components & Template

Web Components adalah cara membuat elemen HTML custom dengan three API: Custom Elements, Shadow DOM, dan Templates. Ini fondasi banyak library UI besar.

13.1 Masalah yang Diselesaikan

Sebelum Web Components, memakai komponen dari library berarti menyalin-menyalin satu file CSS yang sama. Hasilnya: benturan nama class, style yang bocor, dan sulit dipelihara. Shadow DOMegiated menyelesaikan ini dengan mengisolasi style di dalam komponen.

13.2 <template>

Isi <template> tidak dirender oleh browser. Ia hanya menjadi tempat menyimpan HTML untuk di-clone oleh JavaScript:

html
<template id="card-template">
  <article class="kartu">
    <img src="" alt="">
    <h3></h3>
    <p></p>
  </article>
</template>
js
const tpl = document.getElementById('card-template');

function buatKartu({ gambar, judul, deskripsi }) {
  const kartu = tpl.content.cloneNode(true);
  kartu.querySelector('img').src = gambar;
  kartu.querySelector('img').alt = judul;
  kartu.querySelector('h3').textContent = judul;
  kartu.querySelector('p').textContent = deskripsi;
  return kartu;
}

document.body.append(buatKartu({
  gambar: 'kafe.jpg',
  judul: 'Kafe Senja',
  deskripsi: 'Tempat ngopi nyaman di sore hari.'
}));

Kenapa bukan string HTML?

Menyusun HTML dengan innerHTML += berarti browser harus mem-parse ulang seluruh konten setiap kali — lambat dan berisiko XSS bila datanya dari user. <template> + textContent lebih aman dan jauh lebih cepat untuk data dinamis.

13.4 Shadow DOM & <slot>

Shadow DOM membuat "dunia terpisah" di dalam komponen: style dari luar tidak masuk, style dari dalam tidak bocor keluar.

  • attachShadow({ mode: 'open' }) — bisa diakses dari luar (untuk testing/debug).
  • attachShadow({ mode: 'closed' }) — tersembunyi sepenuhnya dari luar.
  • <slot> — "jendela" untuk menyisipkan konten dari luar ke dalam shadow DOM.
  • ::slotted(selector) —|style CSS untuk konten yang masuk lewat <slot> (dari luar ke dalam).
  • :host — selector untuk elemen host itu sendiri.
  • :host-context(selector) — host ketika berada di dalam konteks tertentu.

Kapan perlu Shadow DOM?

Saat kamu membangun library komponen yang dipakai banyak tim dan tidak bolehiene style-nya tertimpa. Untuk aplikasi biasa, komponen dengan CSS Modules atau scoping class yang rapi sudah cukup — Shadow DOM menambah kompleksitas debugging.

  3. Class, atribut, pseudo-class — .kartu, [type], :hover (100 poin)
  4. Tipe, pseudo-element — p, ::before (10 poin)
  5. Wildcard — * (0 poin)

Kalau specificity seri, aturan yang muncul belakangan menang.

Cara praktis

Hindari mengandalkan specificity sebagai cara menyelesaikan masalah. Gunakan !important seminimal mungkin — pada :root untuk custom properties yang memang harus bisa ditimpa, atau sebagai jalan keluar terakhir saat tidak ada pilihan lain. Penyebab utama specificity tinggi biasanya selektor yang terlalu umum. Atasi dengan menyempitkan selektornya, bukan dengan !important.

async function ambilData() {

    if (!res.ok) {
